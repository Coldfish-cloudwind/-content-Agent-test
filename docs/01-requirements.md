# 需求与成功标准

## 用户与业务目标

用户为内容运营人员，需要为指定主题产出一份能在预算和截止时间内完成的内容活动方案。方案包括传播目标、渠道、脚本分镜或图文文案、素材出处、制作任务时序、负责人角色、费用及完成状态。

交付范围是活动内容方案的生成和本地保存。素材均为合成文字描述，生产步骤与费用为模拟值。后续真实剪辑、发布和效果统计在方案中作为交接事项列出。

## 输入约定

| 字段 | 规则 |
| --- | --- |
| campaign_id | 幂等键，1–64 位 ASCII 字母、数字、下划线或连字符 |
| topic | 非空字符串 |
| budget | 非负整数模拟单位 |
| deadline | 含时区的 ISO 8601 时间 |

缺预算或截止时间时返回具体缺失项、incomplete、零工具调用和零费用。无法确定合法任务 ID 时命令返回 error。修正需求后使用新的任务 ID，避免把不同需求混为同一任务。

## 工具与成本

| 工具 | 费用 | 模拟耗时 | 成功产物 |
| --- | --- | --- | --- |
| search_assets | 有匹配且成功时 1 | 3 分钟 | 素材列表及可用版本 |
| estimate_cost | 0 | 0 | 全项目总价、完工时间、缺口 |
| generate_script，studio | 9 | 32 分钟 | 30 秒双素材短片脚本 |
| generate_script，lite | 5 | 9 分钟 | 单素材图文脚本 |
| save_plan | 2 | 3 分钟 | SQLite 持久化方案 |

完整 studio 为 1+9+2=12 单位、38 分钟，lite 为 1+5+2=8 单位、15 分钟。询价在制作前发生，报价包含已成功花费及未来必要费用。失败注入发生于执行前，失败不收费。此结算规则属于本项目的模拟业务约定。真实工具发生部分收费时须扩展账本协议。

## 验收标准

| 验收项 | 可观察标准 |
| --- | --- |
| 正常完成 | completed，四类步骤成功，方案持久化，账单合计一致 |
| 缺预算或截止时间 | incomplete，列出缺失项，工具未执行 |
| 工具失败 | Trace 显示失败，模型选择替代或停止，已成功产物保留 |
| 预算超限 | 观察到 12 超过 10，重估 8 并完成；无可行方案时给出缺口 |
| 重复执行 | 相同 ID 和输入使用已有结果，费用与工具调用次数不增加 |
| 动态决策 | 模型读取真实工具观察后选择下一动作，至少两条不同调整路径 |
| 执行上限 | 单轮默认 10 步，累计 32 步，达到上限返回明确未完成状态 |
| 续跑加分 | 保存失败后复用已生成脚本，只补做保存 |
| 资料不足 | 无素材时停止，部分素材时选支持的版本 |
| 截止时间 | 重估超时版本，制作与保存前再次检查约束 |

所有状态与费用由执行层计算。模型负责选择动作与简要说明依据，步骤成功与否由工具返回及持久化结果确定。

## 后续详细验收

补充的十二类要求对照见 06-requirements-audit.md。支持通过 --catalog 输入同结构的合成资料及费用耗时表。部分成功检索采用每任务一次检索包，费用归首次成功项，失败项为零，包内补取失败 ID 不增加费用。计划版本、DAG、标准工具结果、步骤尝试和状态快照均已纳入报告。
