# 复盘与改进

## 最难的问题

预算重规划需要明确费用何时发生。如果已成功制作高成本脚本，再把最终版本切成低成本并抹掉旧费用，账本会失真。本项目选择先询价、再制作，报价始终加上成功历史开销。已经制作的脚本保留，并限制后续继续使用该版本。

另一个问题是保存失败后的状态一致性。素材、脚本、费用和失败记录必须一起保留，续跑才能只补做保存。SQLite 的原子单行检查点简化了这件事，revision 比较更新防止并发执行重复提交。

## 实际问题与修复

第一次离线生成记录时，Windows 沙箱默认临时目录导致 SQLite 无法创建文件。临时目录改到项目 .runtime 后，用例完整运行。该问题说明复现脚本的运行目录与权限也需要实际验证。

最初环境缺少模型端点凭据。本次提供 api 自动入口，同时通过 bridge 让当前外部模型逐轮读取工具观察并选择动作，保留实际调整轨迹。评估中注明每种记录的来源，供应商模型接入效果仍需补测。

## 学习收获

- 工具调用完成、工具业务成功、活动已保存分别由具体观察和持久化事实确定。
- Agent 的调整应能从前一步工具结果解释，并可以保留已成功步骤。
- 步数、预算、依赖和截止时间应由执行层约束，模型负责业务动作选择。
- 幂等性需要稳定的任务 ID、已保存结果与重复提交保护。
- 测试既要验证最终费用，也要检查失败事件、复用步骤和中间状态。

## 下一步

1. 使用真实 API 在不同主题、预算和时间窗口上重复运行，记录成功率、成本、延迟与失败类型。
2. 增加人工评价，检查方案相关性、素材引用准确性、可执行性和文案质量。
3. 引入真实素材检索和脚本生成服务，设计远程操作幂等键与部分收费协议。
4. 扩展更多版本和素材，以验证模型面对更丰富工具反馈时的选择能力。

上述复盘由 AI 根据本次工程过程形成。候选人个人最难的问题、独立学习收获及修改结果应按实际补充。

## 后续实机加固

用户授权后，AI 继续执行 CLI 子进程与并发实测，修复 HTTP 截断响应、极端时间输入、导出覆盖及费率变动检查问题。测试新增本机 HTTP 服务，但环境返回 WinError 10013，相关测试明确跳过。该轮验证为 35 项中 32 项通过、3 项受限跳过，详见评估文档和实际日志。

## 批量评估与恢复改进

用户要求继续后，AI 增加可运行批量评估、结构检查和待填写的人工评分规则，并实际运行 14 个场景各三次。修复单一候选版本失败后无法续跑的问题，并新增相应证据与测试。该轮测试为 42 项中 39 项通过、3 项本机网络受限跳过。人工评分尚未完成，真实供应商 API 尚未接入。

## 十二类要求核对

本轮由 AI 按用户补充清单自检，确认原版本缺少显式计划版本、DAG、统一工具结果、blocked、步骤幂等键及逐项部分成功重试，随后补齐代码与验证。修复已付费脚本被错误重标计划版本的风险。新增 tests/test_requirements.py，并实际执行 57 项测试与 54 次离线验收。两条新外部模型路径在逐轮观察真实工具返回后执行，原失败结果保留。个人独立修改、真实供应商 API 和人工质量评分仍须据实补充。
