# AI 辅助使用与个人贡献说明

## 项目分工

本项目采用 AI 辅助开发方式。我负责选题与业务目标确认、验收要求细化、迭代任务提出和仓库交付，通过多轮沟通推动项目从核心流程扩展到可核对的状态、费用和恢复机制。ChatGPT Work Mode 中的 Codex 承担主要代码生成、自动运行验证、问题修复及文档整理。

## 我的具体贡献

| 工作环节 | 我的参与与贡献 | 对应成果 |
| --- | --- | --- |
| 业务目标与选题确认 | 选择「内容任务规划 Agent」，确认运营场景围绕主题、预算和截止时间展开，并要求按考核规范形成可运行项目 | 需求文档、CLI 输入与交付范围 |
| 验收标准细化 | 提出并确认覆盖十二类要求的自查清单，明确结构化计划、步骤依赖、计划版本、标准工具结果、预算核算、状态管理、幂等及续跑等检查点 | docs/06-requirements-audit.md、tests/test_requirements.py |
| 关键约束明确 | 强调预算校验、依赖判断、状态流转、幂等控制与费用合计应由确定性代码兜底；要求成功结果可复用、失败记录可追溯 | 费用账本、依赖守卫、检查点与不可变调用记录 |
| 多轮迭代推动 | 在初版完成后持续要求优化与实机验证，并要求按补充清单逐项自检，使遗漏项进入后续实现和回归测试 | 计划版本与差异、blocked 状态、部分成功逐项重试及续跑记录 |
| 验证重点指定 | 要求核对预算超限换方案、工具错误后调整、部分成功保留、重复执行与失败续跑，推动提供实际运行证据 | examples/observed/、examples/test-results.txt、批量评估结果 |
| 提交材料与仓库交付 | 确认提交材料组织方式，创建 GitHub 仓库并完成项目文件上传，整理项目说明及提交信息 | 公开仓库、代码与文档目录、可定位的提交记录 |

其中，验收清单和追加检查要求由我提出，相关程序、测试代码及自动化执行由 AI 辅助完成。测试命令的执行和具体缺陷定位可从项目日志与协作过程核对。

## AI 辅助的使用范围

| 使用环节 | AI 参与内容 |
| --- | --- |
| 方案形成 | 提出 Python 标准库、CLI 和 SQLite 检查点的实现方案，协助组织模块和工具接口 |
| 工程实现 | 生成并修改 Agent 决策循环、模型适配、业务工具、计划审计、费用与时间校验、幂等及恢复逻辑 |
| 合成资料 | 编写合成素材、模拟费用耗时表、测试输入与评分规则 |
| 测试与排错 | 编写测试，调用本地命令执行，检查实际输出，并修复验证中发现的问题 |
| 文档整理 | 根据需求与运行结果形成 README、设计说明、评估文档和复盘材料 |
| 外部模型逐步执行 | 通过 bridge 接收每轮真实工具观察，再选择下一动作，形成可追溯的模型决策记录 |

代码与文档主要由 AI 辅助生成；我的贡献集中在业务要求、验收约束、迭代推动和提交组织。后续由我独立完成的代码修改或额外验证，应继续通过具体提交与运行记录补充。

## 由验收要求推动的关键迭代

| 我提出或强调的要求 | 协作中完成的实现与核对 |
| --- | --- |
| 预算超限后应改选可行方案，并能核算真实已发生费用 | 采用制作前询价、成功费用入账及保存前复核；运行记录体现报价 12 调整为 8 |
| 工具失败和部分成功后应保留成功结果 | 保存已有素材与脚本，增加失败素材 ID 重试和失败步骤续跑 |
| 计划应结构化，重规划后可追溯 | 增加带依赖的任务计划、版本历史、触发观察、变更差异和结果引用 |
| 前置失败应阻断后续关键步骤 | 增加 blocked 状态与工具前置条件校验，测试依赖不足时拒绝保存 |
| 重复执行应避免重复扣费或重复保存 | 增加任务与运行标识、步骤幂等键、已保存结果复用及并发提交保护 |
| 验收应有可运行测试和实际材料 | 增加针对性测试、CLI 子进程验证、执行 Trace、中间快照及批量评估 |

在这些需求基础上，AI 的自动检查还定位并修复了 HTTP 截断响应、极端时间输入、导出覆盖、费率变化检查及已付费脚本被错误重标计划版本等具体问题。

## 已留存的验证结果

- 可执行测试共 57 项，54 项通过，3 项本机 HTTP 联测因环境网络权限限制跳过。实际日志见 examples/test-results.txt。
- 离线批量验收覆盖 18 个调用场景，各重复 3 次，共 54 次，验收预期匹配和结构检查均通过。结果见 examples/audit-evaluation/summary.json。
- 外部模型逐步执行路径包括 examples/observed/audited_live_budget.json 和 audited_live_error.json，分别体现部分成功恢复与超预算调整、工具失败后复用成功结果并选择替代方案。
- 输入、实际输出、工具参数、错误、费用、计划版本和快照均保存在项目中，便于评审核对。

上述命令与自动化验证由 AI 工具实际执行。本人在协作中提出验收要求和追加核查任务，个人独立运行或手动代码调试的新增结果需另行记录。
